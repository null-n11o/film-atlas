## 利用者と目的

映画を観る前後に、作品の舞台となる歴史・文化や制作背景を知りたい人を対象とする案。歴史の予備知識がなくても概要を読み始められ、詳しく知りたい人は出典へ進める構成を目指す。実利用の規模と頻度は未検証。

本人の関心から生まれたサービスを実際に使える開発事例として示す。LOでの紹介と、個人noteを通じたKCP認知も検討する。初期版の成功を売上だけで判定しない。

## 主要な利用の流れ

1. 作品名・公開年を見て対象作品を選ぶ。
2. ネタバレを含まない背景の概要を読む。
3. 気になる解説を選び、その歴史・文化が作品のどこに関係するかを知る。
4. 場所や時代を地図・年表・文章で確認する。
5. 根拠資料を開くか、同じ背景を持つ別作品へ進む。
6. 作り手に関心を持った場合、運営者紹介から個人noteへ進む。

監督・制作、俳優・役作りは作品との接点が確認できる場合に紹介する。考察は歴史解説と区別して読む。情報量を揃えるための埋め草を作らない。

## 画面ごとの受入条件案

| ID | 対象 | 確認する利用者の操作と結果 |
|---|---|---|
| R01 | 作品一覧 | 作品名と公開年から作品を選べる。同名・別年の作品を取り違えない |
| R02 | 作品概要 | 初回は核心的な筋書き・結末を含まない概要が見える。詳しい解説の入口と所要の目安が分かる |
| R03 | 背景解説 | 背景の説明と映画との接点を区別して読める。どの出典が説明を支えるか分かる |
| R04 | 出典 | 資料名・著者または発行主体・URLまたは書誌情報・確認日が分かる。外部資料を開いて本文へ戻れる |
| R05 | 関係 | 制作者が明示した着想源、史実・原典との対応、編集者の比較・考察を表示で区別できる |
| R06 | ネタバレ | 初期状態で隠れた内容は明示操作で開く。閉じた場合は地図・年表・関連リンクも同じ状態へ戻る |
| R07 | 地図 | 場所を選ぶと関連解説へ進める。地図が使えない環境でも場所の一覧から到達できる。架空の場所を史実の場所と混同しない |
| R08 | 年表 | 出来事の前後関係と作品との接点を読める。映画の公開年、劇中の年代、史実の年代を区別できる |
| R09 | 関連作品 | 関連の理由を読んで別作品へ進める。根拠のない影響関係を表示しない |
| R10 | 人物 | 人物と作品との接点、本人の発言と編集者の解釈を区別できる。人物ページから作品へ戻れる |
| R11 | 個人note | 確認済みのURLがある場合だけ外部リンクを表示する。未確定のURLに仮リンクを置かない |
| R12 | 空・不明 | 解説や関係が未掲載の場合は誤った情報で補わない。不明なURLでは作品一覧へ戻れる |
| R13 | モバイル・操作性 | 小画面でも本文が横にはみ出さない。キーボードで主要な操作ができ、選択状態とフォーカスが分かる |

受入条件の実施手段は詳細設計で選ぶ。実装に合わせただけのテストを増やさず、作品の識別、出典と関係の整合、ネタバレ制御、画面間の移動を重点に検証する。

## 情報に必要な項目

| 対象 | 保持する情報の案 |
|---|---|
| 作品 | 識別子、邦題・原題、公開年、概要、背景・人物・関連作品への参照 |
| 背景解説 | 識別子、題名、短い概要、本文、対象となる作品、根拠、ネタバレ区分、確認状況 |
| 人物 | 識別子、名前、役割、作品と関係する背景、出典 |
| 場所 | 識別子、名称、実在・架空の区分、位置または位置不明の表示、対象時代、出典 |
| 出来事 | 識別子、年代または範囲、確実性、説明、作品・背景・場所との関係、出典 |
| 関係 | 接続する対象、関係の種類、理由、根拠、確認状況、ネタバレ区分 |
| 出典 | 識別子、資料名、著者・発行主体、URLまたは書誌情報、該当箇所、確認日 |

これは内容管理の要求であり、データベース採用を意味しない。保存方式、公開データの形式、画面生成方法はハーネス選択後の設計で決める。

## 初期コンテンツ案

『DUNE/デューン 砂の惑星』（2021）を最初の候補とし、『アラビアのロレンス』（1962）と『オッペンハイマー』（2023）を追加候補とする。CEOの確定選択ではない。掲載する歴史的説明や作品間の関係は、この文書では確定していない。

最初の1作品で概要・歴史文化・出典・人物への移動を成立させる。残りの候補は利用体験を確かめるために追加し、関係の根拠が見つからない場合は無理につながない。候補の変更が必要なら理由を記録する。

初期版の本文は完成した解説として作り、ダミーの引用や実在しない参考文献を混ぜない。公開可能なデータへの移行は、出典の中身と素材の利用条件を確認してから行う。

## 初期範囲から外す案

会員登録・決済・利用者投稿・コメント・リアルタイムAI回答・映画本編の配信・自動的な全作品収集。初期の保存機能や検索の必要性は作品数と利用状況から判断する。

## 計測と公開前の条件

作品閲覧、背景閲覧、別作品への移動、再訪、個人noteへの外部リンク操作を測定候補とする。導入する計測基盤と公開前の確認事項は設計で決める。未設置の計測を稼働済みと記載しない。

ユーザーの自由記述や個人情報を集める機能は初期案に含めない。問い合わせ先を載せる場合は実在する確認済みの窓口だけを使う。noteの記事・プロフィールURLも確認後に設定する。

## 詳細設計へ引き継ぐ論点

- ハーネス選択、仕様・実装計画の保存先。
- サーバーの要否、静的な内容の管理方法、地図・年表の描画と代替表示。
- ネタバレ設定の有効範囲、直接URLを開いたときの挙動、検索・ページ情報への漏出防止。
- 出典・関係・素材の公開条件を検証する方法。
- 対象作品、紹介するnoteのURL、計測と運用費の上限。
