ユーザーはSuperpowersと「1作品を完成させてから追加する」進め方を選択した。最初の1作品で概要・背景解説・出典・人物・地図・年表・ネタバレ制御を検証し、追加作品で作品間の探索を確認する。

本書の技術構成、データ形式、画面の細部は2026-09-23の「OKです」で設計として承認された。作品名と最終的な掲載本数は未確定。候補名の存在を掲載決定や内容確認の完了として扱わない。

要求の参照先は[要求案](../../2026/09/requirements.md)、準備の範囲は[上位PLANの参照コピー](../../2026/09/PLAN-20260923-300-film-atlas.md)、作業規約は[AGENTS.md](../../../AGENTS.md)。会社側の企画正本と未決事項は指定されたローカルパスに見つからず、未確認である。本書は参照コピーと要求案に基づく。正本との差異は、所在が確認できた時点で照合する。

## 2. 利用体験と初期版の完成条件

映画を観る前後の利用者が、予備知識なしに短い概要から読み始め、背景の説明と作品との接点を区別しながら根拠資料へ進める体験を作る。作品理解を優先し、関係が確認できた場合に別作品や背景知識へ探索を広げる。

最初の1作品の完成条件は次のとおりとする。

- 一覧から作品名と公開年で作品を選び、ネタバレを含まない概要を読める。
- 内容確認済みの背景解説を1件以上掲載し、説明と作品との接点から該当出典へ進める。
- 作品との接点を確認した人物を1人以上掲載し、作品と人物の間を移動できる。
- 根拠を確認した場所・出来事をそれぞれ1件以上掲載し、地図・年表と文章の一覧から同じ解説へ到達できる。
- ネタバレの表示・非表示を切り替え、本文と探索先の表示が一致する。
- モバイルとキーボードによる操作、未知のURL、通信・保存の失敗を受入条件で確認する。

件数は動線を確認するための最低条件であり、解説の水増しを求めない。最初の候補で確認可能な資料が揃わない場合は、欠けた内容を創作せず、候補変更または完成範囲の変更をレビューする。ネタバレを含む実コンテンツが不要な作品では、制御の検証にテスト専用データを使う。

別作品への移動は追加段階の受入対象とする。最初の1作品では関連作品欄を空にできる。関係が確認できない作品を追加しても、影響関係や共通背景を作って埋めない。

初期版には会員登録、課金、投稿、検索、保存、利用者向けAI生成、管理画面を含めない。素材の入手や実際の内容調査、公開先の契約は本設計作業と分ける。

## 3. 構成の比較と推奨案

| 案 | 内容の編集と配信 | 利点 | 初期版での負担 |
|---|---|---|---|
| A：ローカルファイルと静的生成（推奨） | Git管理の内容を検証し、HTMLと必要なデータを生成 | 内容とコードの変更を一緒に確認でき、閲覧用サーバーの処理や認証が不要 | 更新のたびに再生成が必要。編集者はファイルを扱う |
| B：CMSと静的生成 | 管理画面で内容を編集し、取得後に生成 | 編集者がGitを使わず更新できる | CMSの認証・設定・運用が増える |
| C：データベースと動的配信 | サーバーが閲覧時に内容を取得 | 投稿や利用者別の状態を追加しやすい | 今回使わないサーバー・認証・永続化の設計が増える |

Aを採用し、Astro、TypeScript、通常のCSSで構成する。本文はMarkdown、構造化項目はJSON、本文の属性はfrontmatterに保存する。MDXや任意HTMLの埋め込みは初期版で許可しない。ネタバレ切替と地図の選択操作には小さなクライアントスクリプトを用い、UIフレームワークは追加しない。

Astroはローカルファイルの内容をビルド時に読み込み、操作が必要な部分にJavaScriptを追加できる。この機能を根拠に選定した。バージョンと対応するNode.jsは実装計画で公式の対応条件を確認して固定する。現時点では依存関係を導入していない。

技術資料（2026-09-23確認）：[Content collections](https://v6.docs.astro.build/en/guides/content-collections/)、[Islands architecture](https://docs.astro.build/en/concepts/islands/)。

## 4. 責務とデータの流れ

| 単位 | 入力 | 責務と出力 |
|---|---|---|
| 内容読込 | MarkdownとJSON | スキーマで形式を確認し、識別子付きの内容へ変換 |
| 内容検証 | 全レコード | 参照整合性、確認状態、出典、素材条件、ネタバレ指定を検証 |
| 公開データ生成 | 検証済みのレコード | 公開対象だけを選び、通常表示用とネタバレ表示用に分離 |
| 表示条件の判定 | 対象の必要許可と作品別の許可集合 | 本文・関係・場所・出来事を表示できるか判定 |
| ページ生成 | 通常表示用の公開データ | 一覧、作品、背景、人物、運営方針、404のHTMLを生成 |
| ブラウザー操作 | 明示操作と公開済みの追加データ | 許可状態を更新し、該当画面の表示を再計算 |

画面から原稿を直接読み込まない。公開データ生成を通った内容だけをページと追加データに渡す。表示条件の判定は画面ごとに作らず、共通の純粋関数としてテストする。

予定の配置は `content/` に原稿、`src/lib/content/` に読込・検証・公開データ生成、`src/lib/spoilers/` に表示条件、`src/components/` に画面部品、`src/pages/` にルート、`tests/fixtures/` にテスト専用データとする。実装計画でファイル単位へ分ける。

テスト専用データは実在の出典を装わない。公開処理は `content/` のみを読み、テストデータを本番成果物へ含めない。編集メモと確認前の素材も配信ディレクトリに置かない。

## 5. 内容モデル

識別子は種類ごとに一意とし、URL用のslugと表示名を分ける。本文を変更しても参照先の識別子を維持する。作品名が同じでも公開年と識別子で区別する。

### 共通項目と記述の単位

公開可能なレコードは `id`、`status`、`revision`、`review` を持つ。状態は `draft`（編集中）、`reviewed`（人による内容確認済み）、`published`（公開対象）、`withdrawn`（掲載取り下げ）とする。`review` は確認者、確認日、確認したrevisionを保持する。内容変更時にrevisionを進め、旧revisionの確認では公開できないようにする。

説明は段落相当の記述ブロックに分け、各ブロックが `id`、`kind`、本文、`evidenceRefs`、`spoilerWorkIds` を持つ。`kind` は歴史・背景の説明、作中の描写、本人の発言、編集者の解釈を区別する。引用する場合は発言者、原文の位置、引用範囲、翻訳の有無も保持する。

`spoilerWorkIds` はその記述を読む前に許可が必要な作品IDの集合とする。空集合はネタバレなし。未指定は検証エラーとし、空集合と推定しない。複数作品の内容に触れる記述は全作品への許可が揃った場合だけ表示する。

タイトル、概要、リンク文言、画像の代替テキストも本文と同じ確認対象にする。各ページには必ずネタバレのない `safeTitle` と `safeSummary` を用意する。情報を含む正式な見出しには独自の表示条件を付ける。

### レコードの種類

| 種類 | 主な項目と制約 |
|---|---|
| 作品 | 邦題、原題、公開年、safeTitle、safeSummary、記述ブロック。公開年は劇中年代と分離 |
| 背景解説 | 分類、safeTitle、safeSummary、背景説明ブロック、作品との接点ブロック。接点には対象作品を指定 |
| 人物 | 表示名、識別用補足、背景ブロック。参加作品と役割は関係レコードで保持 |
| 場所 | 名称、実在・架空の区分、対象時代、位置の精度、根拠。実在は緯度経度または位置不明。架空はworldIdと説明を持ち、地球の緯度経度を禁止 |
| 出来事 | 年代領域、開始・終了、表示用年代、確実性、説明ブロック。領域は史実・劇中・公開を区別 |
| 関係 | 型付きの始点と終点、種類、理由ブロック、根拠、spoilerWorkIds。種類は着想源の明示、史実・原典との対応、共通背景、編集者の比較、参加など |
| 出典 | 資料名、著者または発行主体、URLまたは書誌情報、参照日。URLのみで確認済みとはしない |
| 根拠 | 出典ID、該当ページ・章・時刻など、支える記述ID、確認メモ。1つの出典と個別の主張を結び付ける |
| 素材 | ファイル、制作者、取得元、利用条件、確認日、必要な表示、改変の有無、確認者。引用にも適用 |

作品と背景、背景と場所・出来事・人物の接続も関係レコードにまとめる。逆方向の一覧は生成し、両側の配列を手作業で重複管理しない。作品への単なる参加と、作品が人物の経験から影響を受けたという主張は別の関係にする。

年代は西暦の整数年と範囲を基礎とし、紀元前1年を内部値0、紀元前2年を-1として比較する。表示には「紀元前」を使う。概算・範囲・不明を区別し、年代不明を0年に変換しない。架空世界の年代はworldIdごとに並べ、史実と同じ軸に置かない。並べる根拠がない項目は「年代不明」欄に置く。

## 6. 内容確認と公開条件

編集者が原稿を作り、人の確認担当が出典の該当箇所と記述の対応、区分、ネタバレ、素材条件を確認する。確認担当の実名・担当範囲は最初の実コンテンツ制作前に決める。AIによる下書きだけでは `reviewed` に移さない。

公開データを生成する際は次を検証する。

1. IDの重複、存在しない参照、不正な種類の接続、年代範囲の逆転、座標の範囲外をエラーにする。
2. `published` の全レコードに現revisionの確認記録を求める。根拠が必要な記述・関係には確認済みの根拠と出典を求める。
3. 公開する関係の両端も `published` に限る。非公開の参照先を含む関係は黙って落とさず、公開状態の不整合としてビルドを失敗させる。
4. 素材と引用には利用条件の確認記録を求める。確認前の素材は画像・引用として出力しない。
5. 着想源の明示には本人の明示的発言などを支える根拠を必須にする。類似性の記述を着想源へ自動変換しない。
6. ネタバレ条件と安全な表示用文言を検証し、出典の題名や関係の理由にも条件を適用する。

機械検証が確認できるのは記録の存在と整合性である。資料の信頼性、解釈の妥当性、利用条件を満たすかどうかは人が判断する。

公開取り下げは `withdrawn` への変更と、その対象へ向く公開関係の修正を同じ更新で行う。取り下げたページは次の生成で404とし、内容を残したまま一覧だけから隠さない。再公開する場合は再確認する。旧配信物の置換は公開時の運用手順で確認する。

## 7. 画面と遷移

| URL案 | 内容と操作 |
|---|---|
| `/` | 作品名・公開年・安全な概要の一覧。公開済み作品だけを表示 |
| `/works/[slug]/` | 概要、読む目安、背景・制作・役作り・考察への入口、人物、地図、年表、関連作品。根拠のある欄だけを表示 |
| `/backgrounds/[slug]/` | 背景説明、作品別の接点、記述ごとの出典、関連する場所・出来事・作品。作品が複数でも解説を複製しない |
| `/people/[slug]/` | 人物と各作品の接点、発言・解釈の区別、参加作品へのリンク |
| `/about/` | 運営者、制作意図、出典・訂正方針。確認済みの場合のみnoteと連絡先を掲載 |
| `/404.html` | 見つからない旨と作品一覧へのリンク。候補の非公開タイトルは示さない |

地図・年表は作品ページ内の領域とし、初期版では専用ページを増やさない。解説のリンク先には見出しを付け、ブラウザーの戻る操作を保つ通常のリンクを使う。出典は記述から同ページの資料情報へ移動でき、外部URLがあればリンクする。書籍のみの資料は書誌情報と該当箇所を表示する。

所要時間は表示中の文字数を毎分500文字で換算して切り上げ、1分を下限とする。「読む目安」と表示し、読了の測定値として扱わない。

空の分類見出しは表示しない。関連作品がない場合は「関連作品はまだ掲載していません」と表示し、関係が存在しないとは断定しない。隠れている内容を示す場合も、具体的な題名や件数で筋書きを推測させない。

幅320px・390px・1280pxで本文の横はみ出しを確認する。見出し構造、本文へのスキップリンク、フォーカス表示、操作名、選択状態を用意する。色やホバーだけで意味を伝えない。200%拡大時も本文と操作に到達できることを確認する。

## 8. ネタバレ制御

### 状態の範囲

初回は全作品を非許可とする。作品ごとに「この作品のネタバレを表示」を設け、許可した作品IDの集合を同じタブの `sessionStorage` に保存する。同じタブ内の画面遷移・再読み込みで復元し、保存先が利用できない場合は現在のページ内だけで有効にする。新しいセッションは非許可を初期値とする。

URLのクエリーやハッシュでは許可を変更しない。直接URLを開いた場合も同じ判定を通し、必要な許可がなければ安全な概要と切替操作だけを表示する。他作品を開いても、その作品を自動的に許可しない。

タブ複製などでセッション状態が引き継がれる環境はあるため、「新しいタブなら必ず非表示」とは説明しない。外部リンクにはセッション状態を渡さず、他サイトのネタバレ制御までは約束しない。

保存値はバージョン付きの作品ID集合として読み取り、不正な形式は空集合へ戻す。ページを離れる際に追加表示を取り除き、ブラウザーの履歴キャッシュから復帰する際にも現在の許可集合で再評価する。閉じた内容が戻る操作で再表示されないことを検証する。

### 表示の判定

対象の `spoilerWorkIds` が許可集合の部分集合である場合に表示する。関係は自身の条件に加え、両端の表示条件を満たす場合だけ表示する。場所のピンと出来事は、現在の作品について表示可能な解説へ到達できる場合だけ表示する。

作品の許可を解除した場合は、本文、見出し、関連リンク、人物との接点、ピン、年表、出典情報を同時に再評価する。地図の表示範囲も表示可能なピンだけから計算する。隠れたピンによって縮尺や中心が変わることを防ぐ。現在のフォーカスが消える領域にある場合は切替ボタンへ戻す。

### 初期HTMLと追加データ

初期HTML、ページタイトル、description、OG情報、構造化データには安全な文言のみを出力する。初期DOMにネタバレ本文を入れてCSSだけで隠す方式は採用しない。通常表示用データにも隠れた題名や理由を含めない。

ネタバレを含む公開済みデータは独立した静的JSONへ出力し、許可後に必要な分を取得してDOMへ追加する。JSONのパスには内容を表さないIDを使う。許可解除後はDOMから取り除き、取得中に解除された場合はレスポンス到着後も表示しない。JSON取得が失敗した場合は安全な概要を維持し、再試行を表示する。

追加JSONは公開コンテンツであり、アクセス制限された秘密情報ではない。直接取得や検索エンジンへの完全な秘匿は保証しない。サイトマップにはHTMLページだけを載せ、公開時には追加JSONへの `X-Robots-Tag: noindex` 設定を確認する。外部の検索結果まで制御できるとは説明しない。

JavaScriptが無効な場合は安全な本文、場所一覧、年表一覧、通常のリンクを利用できる。ネタバレ解除は無効化し、JavaScriptが必要な旨を表示する。HTMLに全文を埋め込む代替動作は設けない。

## 9. 地図と年表

初期地図は、確認済みの実在地点を緯度経度から配置するSVGの概略図とする。緯線・経線と地点名を表示し、「位置関係の概略図」と明記する。国境・海岸線・背景タイルは初期版に含めず、外部地図APIを呼ばない。ズーム・経路検索は範囲外とする。

1地点の場合は過大に拡大せず一定範囲で表示する。同位置の地点はグループ化し、選択後に名称と解説リンクを一覧にする。日付変更線をまたぐ地点は経度を折り返して配置する。場所の記述に対象時代と位置精度を添え、概略図を当時の国境や領域の復元として見せない。

位置不明の地点と架空世界は別の文章一覧に置く。架空の場所に地球上の座標を割り当てない。架空地図や背景地図の追加は、内容上の必要性と素材の条件を確認してから設計を拡張する。

SVGは補助表示とし、同じ情報を持つ場所一覧を常に置く。地図を操作しなくても全リンクに到達できる。地図の描画失敗時も一覧を残す。

年表は縦方向の順序付きリストを基本とする。史実、劇中、公開年を別の見出しに分け、年代の文字列と確実性を表示する。範囲が重なる出来事に厳密な前後関係があるような説明を付けない。各項目から関連解説へ移動できるようにする。

## 10. 計測・運営情報・公開の扱い

初期実装では外部への計測送信を無効にする。開発操作を実利用として集計しない。導入候補のイベントは作品閲覧、背景閲覧、関連作品へのリンク操作、noteへのリンク操作とし、送信先、保存期間、説明方針、費用上限を公開前にレビューする。

noteへのリンク操作は読了・KCP認知・問い合わせと区別する。再訪の計測には継続した識別の方針が必要なため、この段階では計測済みの指標に含めない。

note、問い合わせ先、運営者の公開名は確認済みの設定値がある場合だけ表示する。仮URL、未承認の個人情報、計測用の秘密値を入れない。

今回の設計承認はサービス公開、投稿、支払い、ドメイン取得の承認を含まない。ホスティング先と追加JSONの配信ヘッダー、実コンテンツの最終確認は公開前に確定する。

## 11. 受入条件と検証方法

| 要求 | 合格条件 | 実装後の確認方法 |
|---|---|---|
| R01 | 同名・別年の作品を区別し、選択したIDのページへ進む | テスト専用の同名作品でブラウザーテスト |
| R02 | 初回HTMLに安全な概要と読む目安があり、ネタバレ文字列がない | ビルド成果物の検査とブラウザー確認 |
| R03・R04 | 背景と作品の接点を区別し、各記述の資料と該当箇所を確認できる | 参照検証、実原稿の人による確認、リンク操作 |
| R05・R09 | 関係の種類と理由を表示し、未確認の影響関係を公開できない | 不正データの拒否テスト。作品間移動は追加段階で検証 |
| R06 | 直接URL、再読み込み、戻る操作、許可解除で表示条件が一致する | 複数作品を含むテストデータによる状態テストとブラウザーテスト |
| R07 | 許可された地点だけを表示し、地図なしでも同じ解説へ進む | SVGと一覧の比較、JS無効、地点重複・経度境界・位置不明の確認 |
| R08 | 史実・劇中・公開年、紀元前・範囲・不明を区別する | 年代比較の単体テストと表示確認 |
| R10 | 人物の発言・解釈・作品への接点を区別し、作品へ戻る | 関係検証とブラウザー操作 |
| R11 | 未確認のnote URLを表示しない | 設定なし・確認済みの両ケースで表示確認 |
| R12 | 空欄を創作で埋めず、未知URLから一覧へ戻れる | 空データ、404、取り下げのケースを確認 |
| R13 | 320px幅・200%拡大で本文と操作へ到達し、キーボードで選択できる | ブラウザーで幅・拡大・Tab移動を手動確認 |

特に次の異常系を検証する。

- 公開レコードが下書き、存在しないID、古い確認revisionを参照した場合にビルドを失敗させる。
- テスト専用文字列、非公開原稿、確認前素材が公開成果物に含まれない。
- 複数作品を扱う関係は、片方だけの許可では表示しない。
- ネタバレを閉じたとき、出典の題名、代替テキスト、ピン、年表、リンクにも残らない。
- JSON取得中の許可解除、取得失敗、sessionStorageの例外、ブラウザーの戻る操作で安全な表示を維持する。

テストツールの候補は、内容・表示条件の単体検証にVitest、画面遷移にPlaywrightとする。導入バージョンと実行コマンドは実装計画で確認し、実行確認後にAGENTS.mdへ記録する。本書作成時点でアプリのテスト・ビルドは未実施である。

## 12. 段階とレビュー事項

| 段階 | 成果物 | 次へ進む条件 |
|---|---|---|
| 詳細設計 | 本書 | ユーザーが設計案を確認 |
| 実装計画 | タスク・対象ファイル・順序・検証手順 | CEOが仕様と実装計画をレビューし、実装へ進む判断を記録 |

| 公開準備 | 配信設定と運用条件 | 公開先・費用・内容・運営情報を確認し、明示の公開依頼を受ける |

設計レビューでは、静的生成とファイル編集、作品別・同一タブ内のネタバレ設定、概略図と文章一覧による地図、外部計測を初期状態で無効にする方針を確認する。

対象作品と内容確認担当は最初の実コンテンツ制作前、note URLと問い合わせ先は掲載前、ホスティング・費用上限・計測方針は公開前に確定する。これらが未確定でも、作品に依存しない内容モデルと画面の実装計画は作成できる。

会社側の正本確認とNotionへの結果反映は未実施である。上位PLANの完了条件には残るが、設計承認と準備全体の完了を区別する。
